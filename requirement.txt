# CivicSignal AI

> A responsive web and Progressive Web App (PWA) for multimodal city incident reporting, AI-assisted triage, and operations monitoring.

CivicSignal AI is a portfolio-grade AI engineering project designed for the 2026 software and AI job market. The first version is a mobile-friendly Next.js web application that can also be installed as a Progressive Web App (PWA). It goes beyond a basic chatbot by combining multimodal Hugging Face models, real-world public data, geospatial search, duplicate detection, human review, evaluation, observability, and scalable backend architecture.

The system is designed for non-emergency city service reports such as potholes, broken streetlights, illegal dumping, graffiti, flooding, damaged road signs, sidewalk problems, and noise complaints.

## Project Overview

CivicSignal AI accepts one or more of the following:

- A written complaint
- A photo of the issue
- A recorded voice message
- A location or map coordinate
- A supporting document

It then:

1. Transcribes voice reports.
2. Analyzes uploaded images.
3. Classifies the incident.
4. Extracts important entities such as location, date, and issue type.
5. Finds similar nearby reports.
6. Estimates whether the report is a duplicate.
7. Predicts the responsible city department.
8. Assigns urgency and confidence.
9. Generates a structured incident summary.
10. Sends uncertain cases to a human reviewer.

The platform also includes a city operations dashboard for complaint trends, geographic clusters, service-level risk, model performance, and projected complaint volume.

---

## Platform Experience

CivicSignal AI is initially built as a **responsive web application and Progressive Web App**, not as a native iOS or Android application.

It provides two connected experiences:

### Citizen Reporting PWA

The citizen-facing interface is designed for phones first, but also works on tablets and computers. Users can:

- Take or upload a photo using the phone camera
- Record or upload a voice description
- Enter a written complaint
- Share their current location with permission
- Review the AI-generated report before submission
- Track the processing and review status
- Install the website on their home screen
- Use selected cached screens when network quality is poor

The PWA uses normal browser capabilities such as:

- Camera and file upload APIs
- Microphone and audio recording APIs
- Geolocation API
- Service workers
- Web app manifest
- Push notifications, as a later extension

### City Operations Dashboard

The staff-facing interface is optimized for laptops and desktop screens. It provides:

- Human-review queues
- Incident maps and geographic clusters
- Duplicate-report review
- Agency routing recommendations
- Evidence and confidence inspection
- Forecasting and workload analytics
- Model performance monitoring
- Audit history and reviewer corrections

### Why Start With a PWA?

A PWA keeps the first three-month scope realistic while still providing a mobile-app-like experience. The same frontend codebase supports both citizen reporting and the operations dashboard.

A native mobile client using Flutter or React Native can be added later if the project needs deeper offline support, background uploads, or platform-specific device features.

## Problem

City service-request systems often receive incomplete, duplicated, or poorly categorized reports.

Common problems include:

- Citizens describing the same issue in different ways
- Multiple reports for the same incident
- Incorrect routing to city departments
- Missing location details
- Large volumes of unstructured text
- Delays caused by manual triage
- Limited visibility into complaint trends
- AI systems that provide predictions without evidence

A simple classification model is not enough. A useful system must combine language, images, audio, geography, historical data, uncertainty, and human oversight.

---

## Solution

CivicSignal AI provides a structured multimodal workflow that combines:

- Speech recognition
- Computer vision
- Natural language processing
- Semantic search
- Geospatial search
- Time-series forecasting
- Retrieval-augmented generation
- Human-in-the-loop review
- Background job processing
- Model evaluation and monitoring

The goal is not to replace city workers. The goal is to help them process reports faster while making each prediction explainable and reviewable.

## Example Workflow

A resident uploads:

- A photo showing damaged pavement
- A voice message saying:  
  _“There is a large pothole near the intersection, and cars are swerving around it.”_
- Their approximate location

The system returns:

```json
{
  "incidentType": "Street Condition",
  "subtype": "Pothole",
  "recommendedAgency": "Department of Transportation",
  "urgency": "High",
  "confidence": 0.91,
  "possibleDuplicate": true,
  "duplicateCaseId": "CASE-28419",
  "distanceFromDuplicateMeters": 42,
  "evidence": {
    "visualDetection": "road surface damage",
    "transcriptKeywords": [
      "large pothole",
      "cars swerving"
    ]
  },
  "requiresHumanReview": false
}
```

The report can then be reviewed, corrected, or submitted to a simulated city work-order system.

## Core Features

### Mobile-Friendly Citizen PWA

The citizen portal is designed for one-handed use on a phone and can be installed from a supported browser. It includes:

- Large touch-friendly controls
- Camera capture
- Voice recording
- Location permission handling
- Upload progress
- Draft recovery
- Accessible form validation
- Processing-status updates
- Responsive layouts for mobile, tablet, and desktop

### Desktop Operations Dashboard

City staff receive a separate dashboard layout for reviewing and managing reports. It includes map-based filtering, evidence inspection, reviewer corrections, analytics, and system-health views.

### Multimodal Incident Submission

Users can create reports using:

- Text
- Images
- Audio
- Location
- Documents

### Automatic Speech Recognition

Recorded complaints are converted into text and passed into the same triage pipeline as typed reports.

### Image Understanding

The system identifies visible infrastructure problems such as:

- Potholes
- Garbage
- Graffiti
- Flooded roads
- Broken signs
- Damaged sidewalks
- Fallen trees
- Streetlight issues

### Incident Classification

The platform predicts:

- Complaint category
- Complaint subtype
- Responsible agency
- Urgency
- Confidence
- Human-review requirement

### Duplicate Detection

Potential duplicates are detected using:

- Text similarity
- Image similarity
- Geographic distance
- Time difference

A possible scoring formula:

```text
duplicate_score =
    0.50 × text_similarity
  + 0.20 × image_similarity
  + 0.20 × geographic_proximity
  + 0.10 × time_proximity
```

The weights can later be learned from labeled data.

### Evidence-Backed Predictions

Every prediction should include supporting evidence.

Example:

```text
Predicted category: Pothole

Evidence:
- Image model detected road surface damage
- Transcript contains “large pothole”
- Four similar reports occurred within 100 meters
- Historical records show that similar cases were handled by transportation services
```

### Human Review Dashboard

Reviewers can:

- Correct the complaint category
- Correct the assigned agency
- Mark reports as duplicates
- Approve or reject summaries
- Review low-confidence cases
- Submit model feedback

### Map and Operations Dashboard

The dashboard can display:

- Incident locations
- Heat maps
- Complaint clusters
- Category trends
- Agency workload
- Duplicate-report patterns
- Model confidence
- Predicted complaint volume
- Service-level risk

### Real-Time Processing Status

SignalR can display live status updates:

```text
Complaint received
→ Audio transcribed
→ Image analyzed
→ Similar cases searched
→ Triage completed
```

### Model and Prompt Versioning

Each prediction should store:

```text
model_name
model_version
prompt_version
prediction
confidence
processing_time
reviewer_correction
```

### Graceful Fallbacks

If one model is unavailable, the system should continue when possible.

Examples:

- If image analysis fails, process text and audio.
- If audio transcription fails, keep the uploaded audio for review.
- If the generation model is unavailable, return structured classifier output.
- If confidence is low, require human review.

## Hugging Face Tasks

| Hugging Face task | Use in CivicSignal AI |
|---|---|
| Automatic Speech Recognition | Convert voice complaints into text |
| Image-Text-to-Text | Generate structured descriptions of incident images |
| Zero-Shot Image Classification | Classify visual problems without training a model for every class |
| Zero-Shot Object Detection | Locate objects and hazards in uploaded images |
| Text Classification | Predict category, department, urgency, and priority |
| Token Classification | Extract locations, dates, agencies, and issue-related entities |
| Sentence Similarity | Find duplicate or related complaints |
| Feature Extraction | Create embeddings for retrieval and clustering |
| Summarization | Produce short incident reports and daily summaries |
| Document Question Answering | Answer questions from city policies and service documents |
| Time-Series Forecasting | Predict complaint volume and workload spikes |

The first usable version should focus on five main tasks:

1. Automatic Speech Recognition
2. Image-Text-to-Text or Zero-Shot Image Classification
3. Text Classification
4. Sentence Similarity
5. Feature Extraction

## Recommended Models

These are suggested starting points and can be changed based on cost, latency, licensing, and hardware.

### Audio

- `openai/whisper-small`
- `openai/whisper-large-v3-turbo`

Use a smaller checkpoint during local development and a larger model for deployment testing.

### Image Understanding

- `Qwen/Qwen2.5-VL-7B-Instruct`
- SigLIP2-based zero-shot image classifiers
- OWLv2
- Grounding DINO

### Text Classification

Start with multiple baselines:

- Embedding plus linear classifier
- Logistic regression with TF-IDF
- DistilBERT
- DeBERTa
- Zero-shot classification model

### Embeddings and Similarity

- `BAAI/bge-m3`
- Sentence Transformers models
- Smaller MiniLM-based models for fast local testing

### Forecasting

Start with standard baselines:

- Moving average
- Linear regression
- XGBoost
- Prophet-style forecasting

Then compare them with a Hugging Face time-series model.

## Architecture

```mermaid
flowchart TD
    A[Citizen PWA<br/>Phone, Tablet, Desktop] --> C[ASP.NET Core API]
    B[Operations Dashboard<br/>Desktop First] --> C

    C --> D[PostgreSQL + PostGIS + pgvector]
    C --> E[Object Storage]
    C --> F[Redis Cache]
    C --> G[Message Queue]

    G --> H[Audio Worker]
    G --> I[Vision Worker]
    G --> J[NLP and Triage Worker]
    G --> K[Forecasting Worker]

    H --> L[Whisper Model]
    I --> M[Vision-Language Model]
    J --> N[Classifier and Embedding Models]
    K --> O[Forecasting Models]

    H --> D
    I --> D
    J --> D
    K --> D

    C --> P[SignalR Processing Updates]
    P --> A
    P --> B

    B --> Q[Human Review Workflow]
    Q --> C
```

### Initial Deployment Strategy

Do not begin with many independent microservices.

Start with:

- One ASP.NET Core API
- One Python AI service
- One worker process
- One PostgreSQL database
- One Redis instance
- One message queue

Split services only when load testing shows that independent scaling is useful.

## Machine Learning Pipeline

### 1. Text Preprocessing

```text
raw complaint
→ normalization
→ tokenization
→ token IDs
→ attention mask
→ model input
```

### 2. Basic Classifier

The first learning model can be built from scratch:

```text
tokens
→ token IDs
→ embedding layer
→ pooled embedding
→ linear layer
→ logits
→ softmax
→ predicted category
```

This version reinforces:

- Vocabulary
- Embeddings
- Forward pass
- Backpropagation
- Cross-entropy loss
- Optimizers
- Logits
- Softmax

### 3. Transformer Comparison

Compare the simple model against:

- TF-IDF plus logistic regression
- LSTM
- DistilBERT
- DeBERTa
- Zero-shot classification

Suggested comparison table:

|---|---:|---:|---:|---:|

### 4. Duplicate Detection

```text
complaint text
→ embedding model
→ pgvector search
→ nearby geographic filtering
→ time filtering
→ duplicate score
```

### 5. Multimodal Fusion

Possible fusion strategy:

```text
text embedding
+ image embedding
+ audio transcript embedding
+ geographic features
+ time features
→ fusion layer or scoring model
→ final incident prediction
```

Start with a rule-based weighted score before training a learned fusion model.

### 6. Generation

Use a language model only after classification and retrieval are working reliably.

Generation can be used for:

- Incident summaries
- Reviewer explanations
- Daily operational reports
- Draft work orders
- Natural-language dashboard questions

## Agent Workflow

The project can include a controlled triage agent.

### Available Tools

```text
get_weather(location, date)
search_nearby_cases(latitude, longitude, radius)
retrieve_service_policy(category)
predict_responsible_agency(complaint)
calculate_sla_risk(case)
create_draft_work_order(case)
```

### State Machine

```mermaid
flowchart TD
    A[Understand Complaint] --> B[Collect Available Evidence]
    B --> C[Search for Similar Cases]
    C --> D[Retrieve Routing Policy]
    D --> E[Generate Structured Recommendation]
    E --> F{Confidence High Enough?}
    F -- Yes --> G[Create Draft Work Order]
    F -- No --> H[Send to Human Review]
```

The agent should return structured JSON and should not invent:

- Agencies
- Policies
- Case IDs
- Locations
- Weather data
- Historical records

A report should require review when:

- Model confidence is below a threshold
- Image and text predictions disagree
- Location cannot be verified
- A likely duplicate has conflicting details
- The model cannot identify a valid agency
- A safety-sensitive category is detected
- Required evidence is missing

Reviewer corrections can later be used for:

- Fine-tuning

- Threshold calibration
- Error analysis

- Docker
- Docker Compose
- .NET SDK

git clone https://github.com/your-username/civic-signal-ai.git
cd civic-signal-ai

### Create Environment File

```bash
cp .env.example .env
```

```bash
docker compose up -d postgres redis rabbitmq minio

cd frontend

npm run dev
```
